# Theme packs: full potential spec

Status: **a spec for discussion, not built** except where marked. Six packs exist (Dino Valley, Dragon Castle, Transport Town, Space Station, Ocean Reef, Farm Friends). This document says what a *good* set of packs is, which ones to add, what each contains, and how the pack system should grow so a new pack is cheap, consistent and safe.

## 1. What a pack is (and is not)

A pack is a complete **look and feel**: four companions, an arrival container, a day and night backdrop, a home island, **themed props** for the games, a **reaction set** (how the companion celebrates and how the world answers a success), a particle style and an accent colour. A pack never changes what is taught: sounds, words, games, progress, pacing and the grown-up area are identical in every pack, and switching pack keeps all progress.

Today a pack covers only the first four (companions, arrival, backdrop, island). The animation cycle adds props, reactions and particles (section 5), so a world changes how every game *feels*, not just its wallpaper.

## 2. What makes a good *set* of packs (selection criteria)

1. **Spread of interests** across the 3-5 range, without leaning on stereotypes: animals (wild, farm, sea, bugs), fantasy (dragons, fairies, castles), machines (vehicles, robots, construction), exploration (space, pirates, jungle), nature and weather, and everyday fun (music, bakery, sport).
2. **Distinct at a glance**: different dominant colour and silhouette per pack, so the world picker reads at 80 x 56 px.
3. **Four distinct companions per pack**, distinguishable by shape as well as colour, all friendly (no sharp teeth, no weapons, no frowns).
4. **Culturally broad and neutral**: no real-world cultures as costume, no stereotypes, no religious symbols, no national flags, no real brands or characters. Human figures only where unavoidable and then varied.
5. **Not gendered**: nothing that is "for boys" or "for girls". Both likelihoods in the reviews (vehicles, space, dinosaurs, fairies, pets) are only likelihoods; every pack must be fun for any child.
6. **Learning-compatible**: the world must be calm in the middle of the screen and must not compete with the letters; pictures used by the games (words) stay the same across packs.
7. **Cheap to add**: a pack is data plus art, never new code, once the pack system (section 5) is in.

**Not recommended:** anything based on a real franchise, real brands, school or national themes, religion, or scary themes (haunted house, monsters). A "princess" pack as such (use Fairy Garden and Dragon Castle, which already cover the fantasy appetite without the trope).

### Recommendation

Add **Jungle Safari**, **Robot Workshop**, **Pirate Cove**, **Fairy Garden**, **Music Band** and **Arctic Friends** next (that makes twelve: a real spread, each distinct, none gendered, all low risk). Construction (shares vehicle art) and Weather/Seasons (needs a changing island) are strong second-wave packs. Bakery and Superhero City are popular with children but need the most care.

## 4. Anatomy of a complete pack (the checklist)

For every pack the art and data must provide (existing and new):

1. **Four companions** following the companion contract (shared face parts, growth accessories 0-4, mouth anchor); distinct silhouettes; vivid main colours; a friendly default name each.
2. **Arrival container** per companion (egg, crate, capsule, pod, bud...) and an `arrival` word for captions.
3. **Backdrop**: day and night, 3+ depth layers, a landmark at an edge, quiet centre, a `scenery` group, glowing windows or equivalent at night.
4. **Home island** with a middle-front gap for characters; it should also be able to **grow** (section 5.4).
5. **Props skin** for each prop the games draw: bridge planks, drum, rocket, kitchen pot, safari board cover, treasure chest, rhyme "sky". Done by styling hooks, not by redrawing every game (section 5.2).
6. **Reaction set** (section 5.3): how the companion reacts to *eating a letter / a right answer / a wrong answer / a finale / idle / sleep*, with a signature motion.
7. **Particle style**: what comes out of a celebration (stars, bubbles, hay, sparks, petals, notes...).
8. **Accent colour** and a short blurb for the picker and the grown-up Settings.
9. **Tests**: the contract tests (hooks, ids, growth levels) plus a reaction smoke test.

## 5. Pack system upgrades (technical spec)

1. **Pack manifest**: extend `Pack` with `accent`, `particles`, `reactions`, `props` (all optional, with defaults), so an unfinished pack still works.
2. **Props skins**: `<body data-pack="space">` is set (built). Props are styled through CSS variables and `[data-pack=...]` rules (colours, textures, an optional inline SVG overlay), e.g. bridge planks become stepping stones (space), shells (ocean), hay bales (farm), girders (construction). The game logic and test ids never change.
3. **Reaction API**: `src/ui/celebrate.ts` (`celebrate(el, {level, pack})`) and a `reactions` table per pack: `eat`, `right`, `wrong`, `finale`, `idle`, `sleep`, each a small named WAAPI sequence applied to the companion element. A signature reaction per pack (a digger digs, an alien beams, a jelly glows) replaces "everyone chomps".
4. **Growing island**: the island is a layered scene with named slots (flower, tree, house, flag...). Each secure sound unlocks the next slot in a fixed order, so the island visibly grows with what the child learned and looks different between children without any randomness or loss.
5. **Lazy loading** (only if size matters): packs are code-split and fetched on selection; the default pack ships in the main bundle.
6. **Pack unlocking (product question, not a prototype feature):** in the prototype all packs are free and unlocked. If a real release charges for packs, that is a **grown-up-gated, one-off purchase only**, never shown on a child screen, never a nag (the spec's banned patterns apply). This needs an explicit decision before it is designed.

## 6. Quality bar and process

- **Artist-agent brief** (already used): contract, preview harness, "look at the output", misread list. Extend it with the props and reaction requirements.
- **Review checklist per pack:** recognisable at 64 px; four distinct at a glance; faces clean at all growth levels; day and night both lovely; centre quiet; thumbnail reads at 80 x 56; every id unique; reduced-motion respected; no scary or suggestive shape (check specifically, as an earlier thumb character was redrawn); nothing gendered or culturally narrow.
- **Independent review** after each batch of packs by a fresh reviewer who has not seen the artist's report.
- **Still unverified for every pack:** how children actually name and choose these characters. Only play-testing with consent can show it.

## 7. Cost and plan

Roughly: a creature set plus backdrop plus island is one artist-agent run (about 6-8 minutes and a fresh review); props and reactions are per pack small CSS and animation work once the system exists. The recommended six additions are about six runs plus one integration and review pass. The expensive risks are not art but consistency and review, which is why the spec insists on contract tests and an independent look.
